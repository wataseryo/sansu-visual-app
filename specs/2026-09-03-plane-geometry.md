**テーマ**: 「なぜその公式か」をアニメーションで見せる

VISTAの差別化ポイント。ボタン操作でSVG図形が変形し、公式の根拠が視覚的に理解できる。

#### 実装メモ（Generator向け）

**アニメーション方式**: SVG + CSS transition。Canvasは不要。

**平行四辺形 → 長方形:**
```
[平行四辺形] → 左の三角形を右に移動 → [長方形]
```
- SVGの`<polygon>`を`transform: translateX()`でCSSトランジション
- 所要時間: 1.2秒
- アニメーション前後で「底辺 × 高さ」ラベルが現れる

**三角形 × 2 → 平行四辺形:**
```
[△] + [△を180°回転] → 並べると[平行四辺形]
```
- 2つ目の三角形が回転しながら移動してくる
- 「÷ 2」の理由が視覚的に伝わる

**台形 × 2 → 平行四辺形:**
```
[台形] + [台形を180°回転] → 並べると[平行四辺形]
```
- (上底 + 下底) が「新しい底辺」になることが見える

**画面ID**: `u6-plane-screen`
**トピック切り替え**: タブUIで「平行四辺形」「三角形」「台形」を切り替える（1画面内）

## 制約・前提条件

- 1ファイル構成（index.html）を維持する（JSはapp.jsに追記可）
- SVGはインラインSVGで実装する（外部ファイル不可）
- CSSはstyle.cssに追記する
- 既存の `showScreen()` `initTopicTrial()` の仕組みをそのまま使う
- アニメーションはCSS transitionのみ（JSでclassをトグルする形式）
- 外部ライブラリ追加禁止（CDNも含む）
- モバイル（375px）でSVGが見切れない：viewBox指定 + width:100%で対応

## 未解決の仮定

- SVGアニメーションでiOS Safari上の表示が崩れる場合はCSS transformを使うフォールバックを検討
- 体験問題の「複合図形」は数値のみ回答（図なし）で十分と仮定する

## 品質基準（Evaluator向け）

このスプリントはVISTAのコンセプト実証。以下を全て満たさなければ合格にしない:

1. **アニメーションが意図通り動く**: 3図形すべて。止まる・飛ぶ・崩れるはすべて不合格
2. **公式の根拠が伝わる**: アニメーション後に「だからこの公式なんだ」と分かる説明がある
3. **スマホで崩れない**: 375px幅で全セクションが正常表示される
4. **既存機能が壊れていない**: 速さ・割合・特殊算のトピック画面が引き続き動作する
